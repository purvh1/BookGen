# Requirements: AI Book Generation via AWS Bedrock

## Overview

Allow users to generate a complete book by describing what they want. The system
uses AWS Bedrock (Claude) as the LLM provider to: (1) generate a structured
index (title, author, genre, description, chapter list), then (2) generate the
full content of each chapter one at a time, and finally (3) save the assembled
book as a JSON file in `data/books/` and register it in the SQLite catalog so
it is immediately browsable.

## Requirements

### REQ-1 — AWS Bedrock Provider

**REQ-1.1** The system MUST expose a thin `BedrockProvider` abstraction in
`src/lib/llm/bedrock.ts` that wraps `@aws-sdk/client-bedrock-runtime` and
exposes a single `invoke(prompt: string): Promise<string>` method.

**REQ-1.2** The provider MUST read the following environment variables:
`AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`,
`BEDROCK_MODEL_ID` (default `anthropic.claude-3-5-sonnet-20241022-v2:0`).

**REQ-1.3** The provider MUST throw a descriptive error if `AWS_REGION` or
`BEDROCK_MODEL_ID` is missing at construction time.

---

### REQ-2 — Book Generation Service

**REQ-2.1 — Index generation:** Given a plain-text user description, the
service MUST call Bedrock once to produce a valid book index: `id`, `title`,
`author`, `genre[]`, `description`, `language`, `publishedYear`, and a
`chapters` array of `{ id, title }` stubs (no content yet). The service MUST
derive `id` as a URL-safe slug from the title (e.g. `"My Cool Book"` →
`"my-cool-book"`).

**REQ-2.2 — Chapter generation:** For each chapter stub in the index, the
service MUST call Bedrock once with the full book index as context to produce
the chapter's `content`. Chapters MUST be generated sequentially (not in
parallel) to keep Bedrock token usage predictable.

**REQ-2.3 — Schema validation:** Before saving, the fully assembled book MUST
be validated against the existing `BookSchema` Zod schema
(`src/lib/books/schema.ts`). A validation failure MUST surface a clear error
to the caller (no partial writes).

**REQ-2.4 — Persistence:** On success, the service MUST:
  a. Write the book JSON to `<BOOKS_DATA_DIR>/<id>.json` (absolute path,
     resolved from `process.env.BOOKS_DATA_DIR ?? "./data/books"`).
  b. Call `upsertBook()` to register the book in the SQLite catalog with
     `coverImage` set to `""` (no cover generated) and `filePath` pointing to
     the written file.

**REQ-2.5 — Idempotency:** If a book with the same derived `id` already exists
in `data/books/`, the service MUST reject the request with a clear
`"Book already exists"` error before making any Bedrock calls.

---

### REQ-3 — API Endpoint

**REQ-3.1** A new route `POST /api/generate/book` MUST accept a JSON body:
```json
{ "description": "<user prompt>" }
```

**REQ-3.2** The endpoint MUST return `201` with the new book's metadata (same
shape as `GET /api/books/:bookId`) on success.

**REQ-3.3** The endpoint MUST return `400` for missing or empty `description`.

**REQ-3.4** The endpoint MUST return `409` when the book already exists.

**REQ-3.5** The endpoint MUST return `500` (with an `error` field) for Bedrock
or generation failures, and MUST NOT leave a partial JSON file on disk.

---

### REQ-4 — Property-Based Tests

**REQ-4.1** Tests MUST be written using **fast-check** and run with
**Vitest** (both added as dev dependencies).

**REQ-4.2** A `slugify` utility function extracted to `src/lib/llm/utils.ts`
MUST be property-tested to assert:
  - Output is always lowercase.
  - Output contains only `[a-z0-9-]` characters.
  - Output never starts or ends with `-`.
  - Empty input produces the string `"untitled"`.
  - The function is pure (same input → same output).

**REQ-4.3** The Bedrock provider's JSON-response parser (a helper that extracts
a JSON block from a raw LLM text response) MUST be property-tested to assert:
  - Any string containing a valid JSON object wrapped in ` ```json ... ``` ` is
    parsed correctly.
  - Strings with no JSON block return `null` (not an exception).
  - Malformed JSON inside a code fence returns `null` (not an exception).

**REQ-4.4** The book-index Zod schema round-trip MUST be property-tested with
arbitrary valid index objects (generated by fast-check arbitraries) to assert
that `BookSchema.safeParse(validObject).success === true` for all valid inputs,
and `.success === false` for objects with blank `title`, empty `chapters` array,
or non-positive chapter `id`.
